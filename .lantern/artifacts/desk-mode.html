  • The "→" chip on the box says where the next message goes. "Desk picks" by default; tap it to choose a chat yourself.
  • Under each of your messages, where it went. Tap it to move it to another chat if the Desk got it wrong.
  • The strip at the top: one live line per working or waiting chat.
  • Cards: a short summary of each finished answer, tagged with its chat. Approvals and question cards show in full and are answered right here.
  • Ask the Desk itself: "which chat has X?", "what's waiting on me?", "what did I say about notifications?"

How it works

  • The Desk agent is one long-lived Claude session on the Mac, on a small model (Haiku by default), in no project folder, with no file or shell tools. Its only tools are Lantern's: list the open chats (name, project, workflow, status, a line on what each is doing), read a chat's recent turns, search every chat ever (the existing history search), send a message to a chat, and start a chat (project, workflow, first message).
  • It never approves, answers a question card, closes a chat, or edits code. Starting a chat is said in the feed. When unsure where something goes it asks, with the likely chats as buttons.
  • What it's told is chat names and statuses, plus what it reads. The text of other chats reaches it as quoted data, never as instructions.
  • The feed's summaries come from what the chats already produce: the turn's last message, cut short, plus the existing waiting/approval events. No extra model call per turn.
  • Phone: the same Desk over the existing connection. Two new requests (send to the Desk, read the feed) and one push (a new feed card). It needs a Mac release as well as a TestFlight build.

Build order

  • 1. Mac Desk, read side: Desk is home, live strip, feed of summaries and needs-you cards. Useful alone, with no agent.
  • 2. The Desk agent: the box, routing, "→" chip, moving a misrouted message, asking the Desk about chats.
  • 3. Phone Desk: the same, as the phone's home screen.
