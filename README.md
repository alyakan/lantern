# Lantern for Claude Code

A macOS desktop app for the `claude` CLI you already have. It shows what Claude is doing while it works (tool calls, file edits as diffs, commands still running in the background), and it can walk through a task one reviewable step at a time.

![A Lantern chat with a diff and tool calls](docs/screenshots/chat.png)

## Why

The terminal is a fine place to talk to Claude Code, but a hard place to follow a long turn: edits scroll past, background commands disappear, and a twelve-step plan arrives as one wall of text. Lantern keeps the same Claude Code underneath and gives each piece room to be read.

## Features

- **Readable turns.** Every tool call is a card. Edits and new files show as diffs, and the **side panel** (**Show/Hide side panel**, ⌘\) has the Changes tab, which opens any touched file in a full side-by-side diff, beside Files, Plan, Activity, Tests and Network. The panel always has these six tabs, in this order; one with nothing to show yet says what will show there.
- **Permissions and Workflow.** Every chat has two settings, as chips under the box (and on every window's title bar on a team's canvas). **Permissions** is **Ask** (edits apply and anything else asks you with Allow/Deny) or **Auto** (Claude Code's own classifier approves most actions), and it means the same in every workflow. **Workflow** is **Chat** (a plain conversation), **Step by step** (below) or **Team** (a Lead runs agents: see Teams). Each project remembers its last Permissions and Workflow for its next chat. The command palette has them too ("Permissions: Auto", "Workflow: Team"), and **How the modes work…** in either menu explains each.
- **Start screen and Work menu.** An empty chat, in every Workflow (and the first thing you see), has the box for saying what you're after in your own words, and five cards: **Build**, **Review a PR**, **Debug**, **Design** and **Start a team**. Build, Debug and Design set the Workflow to Step by step in that flavour (Build and Debug offer **Explain as you go**), Start a team sets it to Team, and **Review a PR** lists the repository's open pull requests (from `gh pr list`; if `gh` isn't installed or logged in, it says so, and a PR number can still be typed) and starts a Review on the one you pick. The same five are in the **Work** menu of the menu bar (Start a Team is ⇧⌘N) and in the command palette.
- **Step by step.** A Workflow: one page at a time, with Previous and Next; you approve a page, ask about it, or ask for a change, and only that page is rewritten. Claude suggests how to work from your task, and starts when you say so: **Build** plans and builds a step per page, **Review** walks a pull request or branch a file per page, **Debug** finds the cause from evidence before fixing it, and **Design** reviews the architecture and design (not the code) of a feature, fix or PR: one diagram of the whole thing, then a page per part with concerns you agree with or reject. **Explain as you go** is an option on Build and Debug: every page also explains the why, which you turn on from the flavour menu in the header (or the start screen) and off the same way. The map lives in the side panel's **Plan** tab (with a Map / Plan toggle), drawn like the Activity graph: the layers are bands (UI, business logic, interfaces, implementations, external), each box says whether it's done, in progress or planned, every place an arrow crosses a boundary is marked, Lantern flags an arrow that goes around a layer, and the problems Claude found are listed with them; it lights the part you are on, hovering a box says what it does, clicking one opens its page, and it pans and zooms (drag, pinch or ⌘-scroll, Fit). Any Mermaid diagram in a chat has **Expand**, to look at it full size. You can also pick one yourself; switching partway through a chat, or turning Explain as you go on or off, reminds Claude how it works. Chats saved with the old Learn flavour reopen as Build with Explain as you go on, and ones saved as Architecture as Design. Lantern reads Claude's pages by their headings, and when one doesn't read as a page it tells Claude with your next message, with the headings to use. Claude also has Lantern's own tools: **steps_guide** (the flavours' formats, when it's unsure) and **review_target** (what the side panel's Changes tab compares, so a PR opened mid-review shows straight away). The **Plan** tab in the side panel lists the plan so far (in any Step by step chat; a chat without one says so): each step with what was done, the files it changed and whether it's built, and a click opens its page. In Build, the plan gets **locked**: Claude ends planning by asking you to lock it, builds exactly those steps, and if the build shows the plan needs a change it stops on a **Plan update** page and asks first. Building straight away without a plan has nothing to lock; steps just appear as they're written. **Export** there copies or saves the plan as a markdown document: the Frame, the plan as a table with each step's status, and (optionally) what each step did and the files it changed.
- **Reviews.** Point Step by step at a pull request or branch. Each changed file gets its own page, findings become cards you Agree with or Reject, and your verdicts go back to Claude together. A branch stacked on another is compared with the branch it was built on, not the default branch: Claude names the base in the review's Frame (from the branch's pull request, or its history), and without that Lantern finds the nearest branch it was built on.
- **Tests tab.** Test runs show here when Claude runs your tests: runs of pytest, jest, vitest, cargo and xcodebuild are parsed into passes and failures with file:line links.
- **Network tab.** Until there is a watch it explains Network Monitor and how to add one. With [Network Monitor](https://github.com/alyakan/network-monitor) open as your app's proxy, Claude can search and read the traffic it captured. What Claude reads has auth headers, cookies, and URL parameters and JSON or form fields with credential-like names (`token`, `password`, `secret`, `privateKey`…, and a URL's `key` and OAuth `code`) redacted; anything else in a body reaches it as it is. Tell it which requests matter and it saves a watch for the project: the **Network** tab then lists every matching request as it happens, newest first, with its response as a foldable JSON tree, an outline of its keys (nulls and empty lists marked), and its headers. **Summarize** asks Claude to read a response and put a summary of it above the JSON. Watches and summaries are kept per project; the responses themselves stay in memory, never on disk. The traffic itself isn't per project: Claude in any chat can search and read everything Network Monitor captured, not just the requests a project's watches match.
- **Shell commands.** Start a message with `!` and the box turns into a terminal: `!git status` runs in the chat's folder, its output streams in, and Claude sees it with your next message. Long-running commands (a dev server) keep going until you stop them. When a command asks something (a password, a y/n) you answer it in place; passwords go in a secret field and only to the command.
- **Models chip.** One chip under the box, like "Balanced · Sonnet 5.5", for who does the work in the chat. Its menu lists the harness presets: Standard (your model and effort, Claude Code's own settings), Balanced (Sonnet, with Opus as the advisor Claude consults at decision points and Haiku subagents), Thrifty, Max, or your own, set up in Settings → Harness (**Edit presets…** in the menu). **Customize…** opens the model and thinking-effort choices. On a preset, picking a model or effort makes the chat **Custom**, and the chip and menu say so ("Custom (Balanced, changed)") rather than quietly leaving the preset.
- **Activity tab.** In the side panel ("Each turn's subagents and tools show here" until there's a turn), a live graph of the turn: the Lead at the root, the advisor beside it, subagents below with the model each runs on, and the kinds of tools each uses, with work travelling the edges as it happens. A log of who did what underneath, then what the turn cost per model.
- **Teams.** **Start a team** (the icon beside New chat, ⇧⌘N, or its card on an empty chat) starts a chat that leads a team, or pick **Team** under Workflow in a chat you already have: that chat restarts on the same conversation as the Lead. It starts agents, each in its own git worktree and branch (or in your folder, for work that only reads), sees what they do, and writes to them; and you can talk to any of them directly. The app becomes a canvas of floating chats tethered to the Lead: drag a title to move one, its corner to resize it, the background to pan, pinch or ⌘-scroll to zoom (zoomed out, agents become cards, and a click zooms in). An agent's permission prompts appear in its own window, a pill takes you to the next agent that needs you, and **Team** lists everyone with their latest words and what the team has cost. The team's **Subagents** setting, in the canvas controls, says where the Lead's built-in subagents (the Agent tool, which runs inline where you can't see them) go: **On the canvas** (the default) has the Lead start them as agents instead, **Inline** lets them run in its chat. A plain chat always runs its subagents inline. The Lead can ask you to merge an agent's branch, and only you can approve it: **Review diff** on its card opens the side panel (which stays beside the canvas, and remembers whether it was open) on that branch against its base, and each file listed opens its diff; **Not yet** leaves a quiet line that the Lead was told. The team runs on the Lead's Permissions, and an agent never gets more freedom than its Lead; change them from any window's title bar. A Lead can leave Team once its agents are closed. ⇧⌘C switches between the canvas and the chat view, and a team comes back when Lantern reopens.
- **Settings (⌘,).** General: which events notify you (a turn finishes, Claude needs you, a turn fails), a pause for an hour, the toast sound, the theme (follow macOS, light or dark) and the text size. Your MCP servers with their status: log in, reconnect, turn off, add, edit or remove them (through Claude Code's own settings). An edit can move a server to another scope, and a secret never goes into the project's committed `.mcp.json`. Your skills, the project's and plugins', each with a preview of its file.
- **/ and @ anywhere.** Type `/` anywhere in a message for skills, commands and MCP prompts (sorted into sections, with where each comes from), and `@` to point Claude at a file. MCP tool calls in the chat name their server ("Linear · create issue").
- **Edit files.** The Files tab is an editor with code completion (types and members, hover docs, syntax errors for TypeScript, JavaScript, JSON, CSS and HTML; words from the file elsewhere): change a file, ⌘S to save. The change shows up in the Changes tab like Claude's, and if Claude (or git) changes the file while you have unsaved edits, you choose between your version and the one on disk before anything is overwritten.
- **Read markdown.** A `.md` file opens as a styled document (tables, code, callouts, task lists); **Edit** switches to the editor, and the preview shows your unsaved edits too.
- **Long pastes.** Pasting more than a few lines into the box shows `[Pasted text #1 · 120 lines]` instead of the text; the whole text is sent. Your sent messages show at most three lines, with **Show more** for the rest.
- **Search.** ⌘P finds files, ⌘⇧F searches text (regex, case, whole word), ⌘F searches inside an open file or diff.
- **Chats and History.** A **chat** is what you have open; **History** (⌘K) lists the past ones for a folder, including ones started in the terminal with Claude Code. Several chats can run side by side, with a notice when one finishes or needs you. The chats open when Lantern closes are offered back the next time it opens.
- **Moved folders.** Claude Code keeps a folder's chats (its session files) under the folder's path, so after you move a repository its history stays where it was. **Bring old chats here…** (⇧⌘R, or the folder menu) looks for the places the open project was before: folders with the same name, and places it was already brought over from. It lists each with its chat count, and brings the ones you check into the project's History. Chats are copied in, never moved or overwritten, and the original files stay where they are. **Details** can also bring the MCP servers, permissions and memory Claude Code keeps for the path. History offers the same thing when there are old chats to bring, and the folder menu shows a "moved?" entry for a recent folder whose path has gone, when exactly one folder with the same name is there. Nothing moves until you confirm.

## Requirements

- macOS.
- [Claude Code](https://docs.claude.com/en/docs/claude-code) installed and logged in. Lantern runs your `claude` CLI and never handles authentication itself.

## Install

Download the latest `.dmg` from [Releases](../../releases), open it and drag Lantern to Applications. The app is signed and notarized by Apple, so it opens like any other Mac app.

From 0.1.1 on, Lantern updates itself: when a new release is out, "Update ready" appears under the chat box. Click it to restart onto the new version (a progress screen shows while it installs), or leave it and it installs when you quit. **Lantern ▸ Check for Updates…**, or Settings (⌘,) ▸ Updates, looks right now and shows the download as it goes.

## Build from source

Requires Node 20.19 or newer (see `.nvmrc`) and a stable Rust toolchain.

    npm install
    npm run tauri dev

To build the app bundle:

    npm run tauri build -- --bundles app

Tests: `npm test` and `cargo test --manifest-path src-tauri/Cargo.toml`. Manual checks before a release are in [docs/SMOKE_TEST.md](docs/SMOKE_TEST.md). See [CONTRIBUTING.md](CONTRIBUTING.md) to send a change.
